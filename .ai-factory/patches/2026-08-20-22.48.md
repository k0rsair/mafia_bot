# Allow organizers to start day voting manually

**Date:** 2026-08-20 22:48
**Files:** src/application/PhaseService.ts, src/bot/commands/lobbyCommands.ts, src/app/createBot.ts, tests/unit/application/phaseService.test.ts, docs/game-rules.md, docs/manual-acceptance-checklist.md
**Severity:** medium

## Problem

After dawn, the group could enter `DAY_VOTE` only when the discussion deadline
job became due. An organizer could not begin a vote once discussion was clearly
finished, which made the game wait for the timer unnecessarily.

## Root Cause

The transition from `DAY_DISCUSSION` to `DAY_VOTE` existed only inside the
deadline-processing branch of `PhaseService`; no authorised command invoked
that transition.

## Solution

Added `/startvote`. It is available only in the game group to the lobby creator
or a chat administrator, and only during `DAY_DISCUSSION`. The command calls a
shared phase transition that creates a fresh vote deadline, renders the normal
vote control, and records its message ID. The same optimistic phase-version
lock is used for manual and deadline transitions, so a concurrent deadline
cannot open a duplicate vote.

`[FIX:manual-vote-start]` logs the game, phase and safe trigger metadata for
the transition and the authorised command; no vote choice or role is logged.

## Prevention

- Expose manual phase controls through the existing phase service instead of
  duplicating database writes in Telegram handlers.
- Apply the same phase and management-permission checks to every organiser
  command.
- Test both a valid discussion-to-vote transition and rejection outside that
  phase.
