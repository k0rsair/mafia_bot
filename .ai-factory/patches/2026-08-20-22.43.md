# Limit doctor to one save per night

**Date:** 2026-08-20 22:43
**Files:** src/application/NightActionService.ts, src/infrastructure/repositories/NightActionRepository.ts, tests/unit/application/nightActionService.test.ts, docs/game-rules.md, docs/manual-acceptance-checklist.md
**Severity:** high

## Problem

The doctor action still used an upsert, allowing a player to reopen the night
panel and replace the saved target multiple times in one night.

## Root Cause

Only the commissioner was routed through the create-only action path. The
doctor was left on the generic replaceable action path that had previously been
appropriate before night actions became single-use decisions.

## Solution

The doctor now uses the same atomic `createSingleUseAction` write as the
commissioner. The existing database uniqueness constraint rejects a duplicate
or concurrent second callback. The player receives a role-specific message;
the first target remains unchanged. Logs use `[FIX:doctor-save-limit]` and the
shared repository path uses `[FIX:single-use-night-action]`, with no target or
role data included.

## Prevention

- Route every one-per-night action through a create-only repository method.
- Keep the database unique constraint as the concurrency boundary.
- Test a second callback rather than only the first successful selection.
