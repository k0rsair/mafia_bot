# Limit commissioner to one revealed check per night

**Date:** 2026-08-20 22:23
**Files:** src/application/NightActionService.ts, src/infrastructure/repositories/NightActionRepository.ts, src/bot/views/ephemeralPanelView.ts, tests/unit/application/nightActionService.test.ts, docs/game-rules.md, docs/manual-acceptance-checklist.md
**Severity:** high

## Problem

The commissioner could reopen the night panel, select several players, and see
each result during a single night. The stored action was overwritten, but each
selection still leaked a new check result.

## Root Cause

Night actions used an upsert for every role. This is appropriate for mafia and
doctor choices that are intentionally replaceable, but not for a commissioner
check whose result is revealed immediately.

## Solution

Added an atomic create-only path for the commissioner action. The existing
unique constraint rejects every later or concurrent callback for the same actor
and phase. The user receives a clear rejection; `[FIX:commissioner-check-limit]`
logs only game and phase metadata for accepted, duplicate, and failed writes.

## Prevention

- Treat actions with immediately revealed information as single-use at storage
  level, not only in the UI.
- Preserve database uniqueness checks for concurrent callbacks.
- Test a second target submission and assert that it cannot create another
  private result.
