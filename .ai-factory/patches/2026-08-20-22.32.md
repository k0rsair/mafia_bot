# Add private mafia council with draft confirmation

**Date:** 2026-08-20 22:32

**Severity:** high

## Problem

When multiple mafia players made their night choices, each player could see only
their own immediate acceptance. They could not coordinate from the group-local
private panel, and a choice took effect without an explicit confirmation.

## Root Cause

`NightAction` stored only a target, and every mafia callback used the same
generic upsert path as the doctor. There was neither a confirmation state nor a
mafia-only presentation of the whole council's current choices.

## Solution

Added nullable `confirmedAt` to mafia actions. A mafia target is now saved as a
draft; changing it clears confirmation. The private `🕶️ Совет мафии` shows
every alive mafia's draft or confirmed target only to the mafia who opens that
ephemeral panel. Each mafia explicitly confirms their own draft. At resolution,
only confirmed `MAFIA_KILL` actions are passed to the existing tie-safe mafia
vote resolver. The panel provides a refresh action for seeing teammates' latest
choices.

The migration marks pre-existing mafia actions as confirmed, preserving the
behaviour of a night already in progress during deployment. New choices made
after the migration always require confirmation.

`[FIX:mafia-council]` logs record only game and phase metadata plus safe
counters; no player-to-target relationship is written to logs.

## Prevention

- Keep submission and confirmation as separate persistence operations for any
  secret group decision.
- Filter unconfirmed secrets before applying game effects, rather than relying
  only on the UI.
- Test the service presentation, callback parsing, and resolution boundary.
