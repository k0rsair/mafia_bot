# Confirmed city vote publication

**Date:** 2026-08-22 17:01
**Files:** Prisma Vote schema and migration, city-vote services, callbacks, view, tests, and game documentation
**Severity:** medium

## Problem

Closing nominations with `/closenominations` persisted the transition to the primary vote but did not publish the new control. City votes were also final as soon as a button was pressed, leaving no way for players to review and confirm their choices.

## Root Cause

`publishVoteClosure` always used `context.editMessageText`, which only addresses a callback's source message. A command context has no callback source, so the publication flow failed after the state transition. Votes were stored as a single mutable record without a confirmation state, so every draft was treated as final.

## Solution

The command path now edits the saved public control message through the bot API and then publishes the next round. `Vote.confirmedAt` persists a two-step city vote: selecting a choice creates an unconfirmed draft, confirming it counts it publicly, and changing it clears confirmation. The final confirmation automatically closes every city round. A conditional round close claims the round once before outcomes are resolved, preventing simultaneous final confirmations from applying an outcome twice.

## Prevention

- Publish controls from the durable `controlMessageId` when the transition comes from a command rather than a callback.
- Treat multi-step, concurrent player actions as persisted state, not transient button state.
- Count only confirmed choices in progress, nomination, resolution, and public details.
- Cover both command-triggered transitions and automatic completion from the final confirmation.
