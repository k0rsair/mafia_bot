# Finish a terminal solo-Maniac night

**Date:** 2026-08-22 16:45
**Files:** `src/domain/game/winConditions.ts`, `src/application/PhaseService.ts`, `src/application/TestGameService.ts`, `src/bot/callbacks/ephemeralCallbacks.ts`, `src/index.ts`, focused unit tests, game-rule documentation
**Severity:** high

## Problem

In a test game where Mafia had been eliminated and the Maniac became the only
living player, the game could enter `NIGHT` and never progress. The virtual
Maniac had no legal non-self target, so it recorded no action; the phase then
waited for a required action indefinitely.

## Root Cause

The victory predicate recognised the Maniac only in a two-player
`MANIAC + CIVILIAN` endgame. A lone Maniac was therefore non-terminal, despite
having no possible target. The night-completion path also checked action
progress before checking whether the game had already reached a terminal
state, and final-only completions had no night-resolution narration to trigger
the final reveal.

## Solution

Treat a lone Maniac as a Maniac victory. `PhaseService` now finalizes a
terminal night before calculating required actions and logs a safe
`[FIX:terminal-night]` event. Virtual test players persist an explicit
`MANIAC_SKIP` when no eligible target exists. Callback and polling publishers
now send the final reveal for a terminal night without a dawn resolution.

## Prevention

- Evaluate winner conditions before requiring phase actions.
- Every night actor must have either a legal action, an explicit skip, or a
  terminal-state transition.
- Cover both a solo-Maniac win and a virtual actor without candidates in unit
  tests.
