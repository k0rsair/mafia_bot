# Ensure Prisma Client generation before startup

**Date:** 2026-08-20 21:55
**Files:** package.json, tests/unit/config/packageScripts.test.ts
**Severity:** high

## Problem

On a Linux server, `npm run dev` failed while importing `PrismaClient` from
`@prisma/client`: the generated client was absent after dependency installation.

## Root Cause

`@prisma/client` is a generated package, but the project exposed
`prisma:generate` only as a manual command. A fresh installation therefore had
no lifecycle hook that guaranteed generation before TypeScript code imported it.

## Solution

Added `postinstall`, `predev`, and `prestart` lifecycle scripts that run
`prisma generate`. The generation command writes its own progress and errors to
the deployment log. Added a unit test that requires all three safeguards.

## Prevention

- Keep generated ORM clients behind installation and startup lifecycle hooks.
- Verify a clean server install with a direct ESM import of the generated client.
- Do not commit generated Prisma client output or rely on an existing
  `node_modules/.prisma` directory being copied to the server.
