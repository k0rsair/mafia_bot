# End night after all required private actions are complete

**Date:** 2026-08-20 22:40
**Files:** src/application/NightResolutionService.ts, src/application/PhaseService.ts, src/bot/callbacks/ephemeralCallbacks.ts, src/app/createBot.ts, tests/unit/application/nightResolutionService.test.ts, tests/unit/application/phaseService.test.ts, docs/game-rules.md, docs/manual-acceptance-checklist.md
**Severity:** medium

## Problem

Night always remained active until `NIGHT_DURATION_SECONDS` elapsed, even after
every living player with a night role had completed the required action. This
made an otherwise complete round wait unnecessarily.

## Root Cause

Only `PhaseClock` called the night-resolution branch of `PhaseService`, and it
runs exclusively for a due deadline job. Recording a target or confirming a
mafia draft never evaluated whether the current night was already complete.

## Solution

`NightResolutionService.getActionProgress` now determines completion from the
current alive players and the current phase's actions. A living mafia counts
only after its `MAFIA_KILL` draft is confirmed; doctor and commissioner count
after their matching action exists. Civilians and dead players do not block the
phase.

After every target submission and mafia confirmation, the callback handler asks
`PhaseService` to complete the night. If every required action is present,
`PhaseService` uses the same resolution/finalisation/optimistic transition path
as the deadline handler and publishes dawn immediately. Missing actions leave
the existing timeout intact as a fallback.

`[FIX:early-night-completion]` logs only the game, phase, safe action counts,
and transition trigger; it does not log roles, targets, or private panel data.

## Prevention

- Model the definition of a completed phase in one service, not in callback UI
  code.
- Treat an unconfirmed mafia draft as incomplete at both the progress and
  resolution boundaries.
- Exercise both the all-complete and still-waiting paths in unit tests.
