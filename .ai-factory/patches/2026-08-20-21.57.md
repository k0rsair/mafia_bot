# Allow reviewed Prisma lifecycle scripts under npm policy

**Date:** 2026-08-20 21:57
**Files:** package.json, tests/unit/config/packageScripts.test.ts
**Severity:** high

## Problem

Modern npm on the Linux server blocked install scripts for `@prisma/client`,
`@prisma/engines`, `prisma`, and `esbuild`. The blocked Prisma scripts left the
generated client or its engine unavailable, causing application startup failure.

## Root Cause

New npm install-script policy requires an explicit project allow-list. The
project did not declare trusted packages, so dependency lifecycle scripts were
treated as unreviewed and skipped.

## Solution

Added a source-controlled `allowScripts` policy that permits only the reviewed
Prisma packages and `esbuild`, which is required by `tsx` in development. Added
a test that locks the allow-list to these exact packages.

## Prevention

- Review and explicitly allow every new dependency that requires lifecycle
  scripts; never enable all scripts globally.
- After deployment, run `npm install` followed by `npm run prisma:generate` and
  verify the `PrismaClient` ESM export before starting the bot.
- Investigate audit findings separately with `npm audit`; do not use
  `npm audit fix --force` blindly on a production bot.
