# Stop reopening the mafia kill panel after confirmation

**Date:** 2026-08-21 21:49
**Files:** src/application/NightActionService.ts, tests/unit/application/nightActionService.test.ts
**Severity:** medium

## Problem

After a mafia player confirmed a night kill draft, the bot sent another private
mafia-council panel containing the target-selection buttons. This looked like a
second request to vote for the kill, even when the confirmation immediately
completed the night and moved the game to dawn.

## Root Cause

`NightActionService.confirmMafiaTarget` reused `sendMafiaCouncilPanel` after
persisting a confirmation. That renderer deliberately includes target buttons
and a refresh control, so the confirmation callback created a fresh actionable
panel instead of ending the player's interaction.

## Solution

The confirmation path now persists the draft confirmation and returns to the
callback handler without sending another council panel. The callback handler
can therefore perform the existing all-actions-complete check and publish only
the normal dawn/day messages. A safe `[FIX:mafia-confirmation]` info event
records the game and phase version without roles, targets, or player data.

## Prevention

- A confirmation callback must not re-render controls that invite the same
  action unless the player explicitly needs to revise it.
- Test private-panel delivery counts around every phase-completing callback,
  not only the persistence outcome.
- Keep state transition checks in `PhaseService`; presentation code should not
  create an additional round of inputs after the action is final.
