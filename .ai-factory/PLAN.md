# Implementation Plan: Автоматически подтверждать получение роли

Branch: main
Created: 2026-08-21

## Settings

- Testing: yes
- Logging: standard
- Docs: no

## Goal

Подтверждать получение роли сразу, когда игрок нажимает нейтральную групповую кнопку `🔒 Открыть личную панель`. После успешной доставки личной ephemeral-панели не должна требоваться вторая кнопка `✅ Роль получена`; последний подтвердивший игрок должен по-прежнему безопасно запускать ночь.

## Constraints and decisions

- Ephemeral-панель остаётся единственным местом показа роли; в общий чат не попадает ни роль, ни факт соответствия игрока роли.
- Подтверждение сохраняется только после успешной отправки личной панели: сбой Telegram API не должен оставить игрока подтверждённым без доставленной роли.
- Сохраняются существующие проверки `gameId`, `chatId`, фазы, `stateVersion`, дедлайна и статуса живого игрока; переход в ночь остаётся идемпотентным и optimistic-guarded.
- В логах допустимы только безопасные технические поля (`gameId`, `chatId`, фаза, версия, счётчики); нельзя добавлять роль, текст панели, цель или ID личного сообщения.

## Tasks

### Phase 1: Перенести подтверждение в открытие панели

- [x] **Task 1: Автоматически подтвердить роль после её успешной доставки.**
  - В `src/application/EphemeralPanelService.ts` переработать обработку `ROLE_CONFIRMATION`: при вызове `openPanel` из callback сначала валидировать игру и игрока, отправить персональную панель роли с `callbackQueryId`, затем выполнить идемпотентное подтверждение через `PlayerRepository`, посчитать подтверждения и попытаться начать ночь для последнего игрока.
  - Вернуть из `openPanel` результат, достаточный transport-слою для публикации нейтрального ночного control message, не раскрывая роли. Повторное открытие панели и уже подтверждённый игрок не должны повторно менять состояние или создавать второй переход фазы.
  - Сохранить `restorePanel` как операцию показа панели без побочного подтверждения, поскольку она не является первоначальным кликом получения роли.
  - **Логирование:** `DEBUG` при безопасной маршрутизации открытия панели; `INFO` при автоматическом подтверждении с `gameId`, фазой, версией, `confirmedCount`, `playerCount` и флагом запуска ночи; `WARN` при просроченной/чужой/неактуальной панели; `ERROR` только для технического сбоя adapter/repository. Не логировать роль, текст панели, ночные данные или ID ephemeral-сообщения.
  - **Файлы:** `src/application/EphemeralPanelService.ts`, при необходимости `src/infrastructure/repositories/PlayerRepository.ts` только для сохранения атомарности текущего confirm-path.
  - **Зависимости:** нет.

### Phase 2: Удалить второй шаг UI и подключить переход ночи

- [x] **Task 2: Сделать callback `panel` единственной точкой подтверждения роли.**
  - В `src/bot/views/ephemeralPanelView.ts` убрать кнопку `✅ Роль получена` и связанный с ней callback из карточки роли; при необходимости явно сообщить в приватном тексте, что факт получения уже засчитан.
  - В `src/bot/callbacks/ephemeralCallbacks.ts` после `panelService.openPanel(input)` обработать результат автоматического подтверждения и опубликовать `renderNightControl` ровно один раз, если этим кликом началась ночь; переиспользовать существующую запись `controlMessageId`.
  - Удалить или безопасно обработать устаревший callback `confirm` в `src/bot/callbacks/callbackData.ts` и callback-обработчике, чтобы старые ephemeral-кнопки не могли обойти новую последовательность либо продублировать состояние.
  - **Логирование:** не добавлять успех-логи с персональными данными в callback-слой; оставить безопасные технические `WARN` для отклонённых callback и полагаться на application-service для `INFO` о подтверждении/старте ночи. Убедиться, что путь публикации ночного control message не пишет роли в общий чат или логи.
  - **Файлы:** `src/bot/views/ephemeralPanelView.ts`, `src/bot/callbacks/ephemeralCallbacks.ts`, `src/bot/callbacks/callbackData.ts`.
  - **Зависимости:** Task 1.

### Phase 3: Регрессии и проверка

- [x] **Task 3: Покрыть новый сценарий и проверить существующие гарантии.**
  - В `tests/unit/application/ephemeralPanelService.test.ts` добавить сценарии: клик `panel` доставляет только персональную роль и автоматически выставляет `roleConfirmedAt`; API-ошибка доставки не подтверждает роль; повторный клик идемпотентен; последний игрок запускает ночь только один раз.

  - Запустить `npm run check`. Интеграционные тесты запускать дополнительно лишь при настроенных `TEST_DATABASE_URL` и PostgreSQL; отсутствие этой среды не выдавать за проверку БД.
  - **Логирование:** тестами проверить только безопасные поля событий, если новые записи логгера добавляются; фикстуры используют искусственные Telegram ID, не содержат реальных токенов и не фиксируют текст персональной роли в логах.
  - **Файлы:** `tests/unit/application/ephemeralPanelService.test.ts`, `tests/unit/bot/privatePanels.test.ts`, при необходимости новый `tests/unit/bot/ephemeralCallbacks.test.ts`.
  - **Зависимости:** Tasks 1–2.

## Completion criteria

- Один клик игрока по `🔒 Открыть личную панель` после успешной доставки ephemeral-панели засчитывает получение роли.
- В личной карточке роли больше нет второго обязательного подтверждения.
- При получении последней роли ночь начинается ровно один раз и в группе появляется только нейтральное управление ночью.
- Неуспешная доставка роли, устаревшая панель и повторные callback не нарушают состояние партии и не раскрывают секретные данные.
- `npm run check` проходит; статус интеграционных тестов указан честно.
