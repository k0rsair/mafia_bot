## Product Decisions

- **Стек первого релиза:** Node.js 20+, TypeScript (strict), `grammY` с поддержкой Bot API 10.2 (либо тонкий typed API-adapter для ещё не типизированных полей), PostgreSQL + Prisma для долговечного состояния, Pino для структурированных логов, Vitest для тестов. Бот работает через long polling; запускать второй экземпляр с тем же токеном нельзя.
- **Чат — единственное игровое поле:** лобби, объявления фаз, статусы, дневная дискуссия и голосование живут в групповой теме/чате. Тайные карточки ролей, выборы ночью и ответ комиссара — это **ephemeral messages** в той же группе/супергруппе: Telegram показывает их только выбранному игроку и боту. Сообщения оформляются эмодзи: `🌙`, `☀️`, `🗳️`, `🔍`, `💉`, `⚰️`, `🏁`, `🔒`.
- **Ограничения ephemeral UX:** тайная панель создаётся вызовом `sendMessage` в игровой чат с `receiver_user_id` и, при открытии кнопкой, `callback_query_id`; она может исчезнуть после перезапуска клиента и не гарантированно доставляется офлайн-игроку. Поэтому бот всегда оставляет общее нейтральное действие `🔒 Открыть личную панель`, которое повторно создаёт панель для нажавшего. Игра не опирается на ID ephemeral-сообщения: источником истины остаётся БД. Отдельный чат с ботом и deep-link не используются.
- **Классические роли первого релиза:** мафия, комиссар, доктор и мирные жители. Минимум — 5 игроков. Число мафии `max(1, floor(N / 3))`; комиссар появляется при `N >= 5`, доктор — при `N >= 7`, остальные — мирные. Мафия побеждает, когда её не меньше мирных; мирные — когда мафии не осталось. Доктор выбирает одного игрока (включая себя) один раз за ночь, комиссар узнаёт принадлежность цели к мафии. Изменяемые параметры должны быть централизованы, чтобы позднее добавить дона, шерифа и варианты правил.
- **Границы первого релиза:** одна активная игра на чат, 5–20 игроков, русский интерфейс, длительности фаз настраиваются через переменные окружения. Кнопки голосования не раскрывают индивидуальный голос, а в чате публикуется только итоговый подсчёт.

## Acceptance Criteria

- После добавления бота в группу организатор может создать лобби, участники записываются и выходят кнопками в сообщении лобби, а состав виден всем.
- Игра стартует при минимальном составе; затем каждый игрок открывает скрытую панель роли и подтверждает её получение, не отправляя сообщения в ЛС. Ночь начинается только после всех подтверждений либо отмены игры организатором.
- Ночь последовательно принимает тайные действия мафии, доктора и комиссара; днём бот объявляет результат ночи, принимает групповое голосование и применяет его после таймера либо голосов всех живых игроков.
- Рестарт процесса не сбрасывает активную игру, не даёт повторно применить голос или ночное действие и не раскрывает роли в логах или групповых сообщениях.
- Конец игры показывает победившую сторону и роли всех участников, а новая игра в том же чате может быть запущена после очистки активного состояния.

### Phase 2: Turn engine and player interactions

- [x] **Task 4: Реализовать автомат фаз и скрытую выдачу ролей.**
  - Создать `GameService` и `PhaseService`, которые из готового лобби создают игру, назначают роли в одной транзакции, переводят состояние через `ROLE_CONFIRMATION → NIGHT → DAY_DISCUSSION → DAY_VOTE → … → FINISHED` и сохраняют deadline каждой фазы.
  - После старта опубликовать одно нейтральное групповое сообщение `🎭 Роли распределены` с кнопкой `🔒 Открыть личную панель`. По callback создавать в этом же чате ephemeral-карточку только для нажавшего (`receiver_user_id`) с ролью, краткими правилами и кнопкой `✅ Роль получена`; сохранить только факт подтверждения роли. Ни один публичный текст и callback payload не должны содержать роль.
  - Не считать успешный API-ответ доказательством доставки: при исчезновении/недоставке панели игрок снова жмёт нейтральную кнопку. Дедлайн `ROLE_CONFIRMATION` показывает лишь обезличенное число подтверждений; по истечении времени организатор может продлить фазу или отменить игру, но не узнаёт роли.
  - Спроектировать `PhaseClock` поверх хранимых deadline: он ищет просроченные фазы при запуске и периодически, а не полагается только на `setTimeout`. Все переходы должны проверять фазу и версию состояния внутри транзакции.
  - **Логирование:** `INFO` — начало/окончание фазы, число живых, дедлайн и обезличенное число подтверждений; `DEBUG` — постановка/восстановление задачи таймера и создание ephemeral-панели с техническим ID; `WARN` — уже обработанная/устаревшая задача или недоставленная панель; `ERROR` — ошибка ephemeral API/планировщика. В логах не писать роль, получателя роли или текст скрытого сообщения.
  - **Зависимости:** Tasks 2–3.
  - **Файлы:** `src/application/{GameService,PhaseService,PhaseClock,EphemeralPanelService}.ts`, `src/domain/game/phaseTransitions.ts`, `src/infrastructure/repositories/PhaseJobRepository.ts`, `src/bot/callbacks/ephemeralCallbacks.ts`, `src/bot/views/{phaseView,ephemeralPanelView}.ts`.

- [x] **Task 5: Реализовать скрытые ночные действия с защитой от повторов.**
  - В начале ночи опубликовать нейтральное групповое сообщение `🌙 Ночь. Если у вас есть действие — откройте личную панель` с кнопкой `🔒 Открыть личную панель`. По нажатию проверить игрока/фазу/роль и создать скрытую клавиатуру только для этого игрока: мафии — выбор жертвы, доктору — спасение, комиссару — проверка. Ограничить цели живыми игроками и применить правило доктора из `rules.ts`.
  - Кодировать в callback короткий game/phase/action/target key, проверять владельца роли, принадлежность активной игре, актуальную фазу и версию. Позволить заменить выбор до дедлайна, но хранить единственное актуальное действие; после выбора обновлять только его ephemeral-панель на `✅ Выбор принят`.
  - При закрытии ночи агрегировать выбор мафии с явно определённым правилом ничьей, применить спасение и подготовить результат для публичного рассвета. Результат проверки комиссара показать ему новой ephemeral-панелью, открываемой через ту же нейтральную кнопку; при исчезновении панели он сможет запросить её заново до конца отведённой фазы.
  - **Логирование:** `DEBUG` — валидность действия, создание панели и агрегированный факт «действие получено»; `INFO` — закрытие ночи и число принятых действий; `WARN` — неавторизованная, повторная, просроченная или недоставленная панель; `ERROR` — сбой ephemeral API/сохранения/разрешения ночи. Никогда не записывать цели, роли, проверку или победивший выбор в читаемом виде.
  - **Зависимости:** Task 4.
  - **Файлы:** `src/bot/callbacks/{nightCallbacks,ephemeralCallbacks}.ts`, `src/application/{NightActionService,NightResolutionService,EphemeralPanelService}.ts`, `src/domain/game/nightResolution.ts`, `src/bot/views/ephemeralPanelView.ts`.

- [x] **Task 6: Реализовать дневные объявления и групповое тайное голосование.**
  - На рассвете опубликовать в группе стилизованный результат ночи без лишних тайных деталей, отметить выбытие/спасение согласно правилам, затем начать `☀️ Обсуждение` с дедлайном. После него отредактировать/опубликовать `🗳️ Голосование` с кнопками живых кандидатов и опцией `🤝 Пропустить`.
  - При клике с публичной клавиатуры записывать голос скрыто: не публиковать голосовавшего, отвечать notification только нажавшему, разрешить смену голоса до окончания и показывать в групповом сообщении лишь общий прогресс «голосов: N/M». Разбивать клавиатуру на страницы/строки для лимитов Telegram.
  - Закрывать голосование по дедлайну или когда проголосовали все живые; опубликовать итоговые числа, корректно обработать равенство и пропуск (никто не выбывает) и затем сразу проверить победу/начать следующую ночь.
  - **Логирование:** `INFO` — начало/закрытие обсуждения и голосования, число голосов и обезличенный итог; `DEBUG` — обновление счётчика и pagination; `WARN` — голос мёртвого/неигрока, голос вне фазы или повторный callback; `ERROR` — ошибки транзакции голоса и публикации результата. Не логировать соответствие «пользователь → кандидат» в production-логах.
  - **Зависимости:** Tasks 4–5.

### Phase 3: Reliability, quality, and operations

- [x] **Task 7: Завершение игры, восстановление и защита игровых границ.**
  - Реализовать единый `GameFinalizationService`: после каждого выбытия/ночи определять победителя, публиковать `🏁` с открытием всех ролей, деактивировать игру и позволять создать следующее лобби. Добавить контролируемую `/cancelgame` с подтверждением организатора и нейтральным сообщением в чате.

Снабдить обработчики защитой от чужого чата, старого сообщения, поддельного payload, исключения игрока и сбоя Telegram API. Экранировать пользовательские имена для выбранного Telegram parse mode.
  - Добавить ограничение частоты callback-команд и универсальный responder, который всегда отвечает на callback, чтобы кнопки не «виcели» у игрока.

Роли допускаются только в финальном групповом сообщении, но не в логах.

## Implementation Notes

- Каждая операция, меняющая игру, должна быть идемпотентной и выполнять проверку `chatId + gameId + phase + stateVersion` в транзакции. Таймеры и ephemeral-сообщения являются только UI; источником истины остаются deadline и фаза в БД.
- Ephemeral API разрешён только для групп и супергрупп. Любая ошибка или исчезновение панели должна приводить к возможности повторно открыть её из нейтрального группового control-сообщения, а не к переходу в личный чат или раскрытию тайных данных.
- Нельзя использовать `getChatMember` как единственную проверку участников без проверки Telegram-прав бота; при отсутствии прав следует выдать понятное сообщение организатору, а не завершать игру с ошибкой.
- Перед реальным запуском потребуется создать самого бота в BotFather, добавить его в нужную группу и настроить переменные окружения. Это внешние действия, поэтому они не входят в изменение исходного кода.
